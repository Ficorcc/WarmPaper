这几天模型圈热闹得有点吵：GLM-5.4 用循环层把 750B 吹到对标 2T，GPT-6.2 Sol 登陆 ChatGPT，豆包的「小豆」开始邀请制公测。但我最在意的是 11 月 24 日一个没什么声量的发布——PrismML 的 Ternary Bonsai 2.5 27B。

它有个很朴素的特点：**5.9GB。**一块老显卡、一台 MacBook、甚至 iPad 都能装得下。而这 5.9GB 里装的，是一个能连续做几十步工具调用、自己看测试结果、失败了还能换个思路再试的 Agent 模型。

## 涨得最猛的不是编码分，是「跑完活」的分

官方给的两组数据，我认为比很多榜单第一名更值得看：

| 基准组 | Bonsai 2 27B | Bonsai 2.5 27B |
|---|---|---|
| Agentic 编码（SWE-bench Verified / DeepSWE v1.1 / Terminal-Bench 2.1 均值） | 37.9 | 54.2 |
| 工具调用（AppWorld / τ³-Bench 均值） | 60.2 | 82.2 |

编码分涨了 16.3，工具调用分了涨 22。工具调用这种分数，本质上衡量的不是「你会不会写这段代码」，而是「你能不能在一串动作里不迷路」。

做过多步 Agent 的人都有体会：单步看起来很聪明，二十步以后就开始梦游。第三步读错了文件，第七步重复了第一次已经失败的方案，第十二步忘了最初的任务是什么。小模型在这种场景下不是「能力不够」，是**误差会累加**。PrismML 的 CEO Babak Hassibi 那句话说得挺实在：把模型塞进设备只是一半的挑战，它还得在整个复杂任务的每一个决策里都保持有效。

所以这版 2.5 的重点不是堆数据，而是调「任务展开时的行为」——怎么吸收工具反馈、怎么从失败动作里恢复、怎么少说废话、怎么不重复无用推理。这是工程活，不是刷榜活。

## 为什么这事对个人开发者重要

它有几个具体的落地条件：

- 基于 Qwen3.8 27B 做的三元量化（ternary weights），Apache 2.0，免费下载
- NVIDIA / Intel GPU 走 llama.cpp，苹果设备走 MLX，Mac、iPhone、iPad 都能跑
- 隐私边界清楚：模型推理和敏感信息都留在你自己的设备上

我特别看重最后一条。现在大家用 AI 写代码，默认的把私有仓库丢进云端 API。对个人项目无所谓，对真正有价值的东西——客户资料、内部系统、还没公开的业务逻辑——很多人其实是不愿意的。本地的 Agent 能读私有仓库、改代码、跑测试、看结果再修，这套循环一旦在 5.9GB 的模型上成立，"不用先把代码交出去"就成了可选项。

对独立开发者更现实的一点是成本。验证一个 Agent 想法，以前第一笔开销就是 API 账单；现在可以先在自己电脑上把流程跑通，觉得值了再上云。

## 我的保留意见

三条：

1. **基准是厂商自评。**54.2 和 82.2 都来自 PrismML 自己的评测设置，白皮书也没给出独立第三方的复现。这类数字当趋势看可以，当承诺看要打折。
2. **三元量化不是免费午餐。**权重压到三值，长尾知识和边界情况最先掉。它在典型任务上接近全精度模型，但"接近"这两个字往往藏在那些你不常遇到、遇到就很要命的用例里。官方也提供了更激进的 2-bit 版本，那类文件建议自己拿真实任务测，不要看榜单。
3. **27B 的底子决定了上限。**它的定位是"能干的助手"，不是"能替你架构系统的人"。让它做常规 CRUD、补测试、改 bug、整理文档，很合适；让它设计一个分布式系统，那是另一个价位的事。

## 小结

2026 年下半年模型竞争的焦点，正在从"谁家参数更大"往"谁家能在低配设备上把一件完整的事做完"挪。这两个方向的评价标准完全不同：前者看榜单第一名，后者看一个普通开发者下班前有没有真的省掉两个小时。

我认为 Bonsai 2.5 的意义不在于它有多强，而在于它把"本地 Agent 可用"这条线又往下压了一档——从要一张 24G 显卡，压到一台 16G 内存的笔记本。门槛每降一档，真正折腾的人就会多一批。对独立开发者来说，这比又一个万亿参数模型有意思得多。
